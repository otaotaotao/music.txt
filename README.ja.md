# music.txt

*[English](README.md)*

ブログ記事に音楽を埋め込むためのツールです。本文を貼り付けて、曲を鳴らしたい場所に `[[URL]]` と書くだけで、ブログのHTML編集画面にそのまま貼り付けられるHTMLが生成されます。コードを書く必要はありません。

**公開ページ**
- [ジェネレーター（日本語）](https://otaotaotao.github.io/music.txt/generator.html)
- [Generator (English)](https://otaotaotao.github.io/music.txt/generator-en.html)
- [サンプル記事](https://otaotaotao.github.io/music.txt/sample-walk.html) — 3曲が埋め込まれた散歩日記。スクロールすると曲がクロスフェードします

## 使い方

1. 本文をジェネレーターに貼り付ける
2. 曲を入れたい場所に `[[https://... URL ...]]` と書く（文中でも、独立した行でもOK）
3. 切り替え方式を選んで「HTMLを生成する」を押す
4. 出てきたHTMLをブログのHTML編集画面に貼り付ける

本文中の最初の `[[URL]]` が再生/停止ボタンになります。2つ目以降は曲の切り替えポイントになり、記事末尾に自動で追加できる曲名リストと同じ番号が振られます（曲名・アーティスト名は各サービスから自動取得するので手入力は不要です）。

## 対応サービス

| サービス | 再生制御 | 記事上の見た目 |
|---|---|---|
| YouTube | フル制御（非表示プレイヤー・フェード・自動/手動クロスフェード） | 何も表示されない |
| SoundCloud | YouTubeと同様 | 何も表示されない |
| Spotify | ネイティブの操作のみ | 通常の埋め込みプレイヤーがその場に表示される |
| Apple Music | ネイティブの操作のみ | 通常の埋め込みプレイヤーがその場に表示される |
| Bandcamp | ネイティブの操作のみ | 通常の埋め込みプレイヤー、生成できない場合はただのリンク |

YouTubeとSoundCloudはどちらも音量操作を含むJS APIを公開しているので、非表示プレイヤー・フェード・自動クロスフェードが実現できます。SpotifyとApple Musicは埋め込みAPIから音量操作を意図的に公開しておらず、Apple Musicのプログラム制御（MusicKit JS）には有料のApple Developer Program登録も必要です。そのため、この3サービスへのリンクは通常の見えるプレイヤーとして、各サービス自体の再生ボタンで聴く形にしています。

## 切り替え方式

- **手動のみ** — 読者が切り替えボタンを押したときだけ曲が変わります。
- **自動トランジション**（デフォルト） — その曲の段落までスクロールすると自動でクロスフェード。保険として手動ボタンも表示されます。
- **段落タップ送り** — 最初の段落だけ表示された状態で始まり、「▼」をタップするたびに次の段落が現れます。曲の切り替えもスクロールではなくこのタップに連動します。音楽だけでなく読み方自体が変わる形式です。

## iOSについて

モバイルSafariにはここで無視できない癖があります。埋め込み動画・音声に対するJSからの音量変更を暗黙に無効化しており（本ツールの不具合ではなく、プラットフォーム側の仕様です）、また YouTube/SoundCloud の iframe に対する最初の `play()` 呼び出しは、実際に再生が始まるまで数回リトライが必要になることがあります。生成されるスクリプトはどちらにも対策していて、iOSではスムーズなフェードの代わりにミュート切り替えを使い、再生の確認が取れるまで数回リトライしてから諦めます。ただ、サードパーティ製プレイヤーを埋め込むという性質上、これは今のところ一番ざらついている部分です。もし自動での切り替えが無音のままだったとしても、常時表示されている再生ボタンをもう一度押せば、手動で「確実に鳴らす」操作として機能するはずです。
